# Publication Safety Skill

## Use when

- preparing a public repo update
- answering public support
- publishing examples
- creating launch material

## Checks

- no secrets or credentials
- no real private host paths
- no personal/private context
- no customer/client data
- no private emails, account IDs, or chat IDs
- no unwanted AI attribution signals
- examples use placeholders or fake data
- runtime/provider details are isolated in adapters

## Review

Run automated scans where available, then manually inspect high-risk files.

## Escalation

Escalate if a file may contain private operational details, security-sensitive guidance, or public commitments.
